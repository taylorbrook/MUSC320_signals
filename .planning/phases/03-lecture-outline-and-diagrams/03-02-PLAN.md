Create `patches/three-level-comparison.maxpat` -- a single .maxpat with three columns comparing control-rate, signal-rate, and sample-rate processing.

Per CONTEXT.md: "A Max patch (not a static diagram) showing three computational levels side-by-side: control-rate (metro), signal-rate (phasor~), and gen~ (counter or codebox)."

**Three-column architecture (from RESEARCH.md Pattern 5):**

**LEFT COLUMN: Control Rate (metro)**
- Title comment: "CONTROL RATE" (large, bold)
- Subtitle: "~1,000 updates/sec (scheduler rate)"
- metro 500 -> counter 0 100 -> number box (shows staircase updates)
- toggle to start/stop the metro
- scope or multislider showing the staircase pattern (2 updates/sec visible)
- Comment: "metro fires individual messages -- you see discrete jumps"

**CENTER COLUMN: Signal Rate (phasor~)**
- Title comment: "SIGNAL RATE (MSP)" (large, bold)
- Subtitle: "44,100 samples/sec (audio vectors)"
- phasor~ 2 -> *~ 100 -> number~ (shows continuous ramp 0-100)
- live.scope~ showing smooth ramp waveform
- ezdac~ to enable DSP (shared or per-column)
- Comment: "phasor~ generates 44,100 values per second -- smooth and continuous"

**RIGHT COLUMN: Sample Rate (gen~)**
- Title comment: "SAMPLE RATE (gen~)" (large, bold)
- Subtitle: "44,100 samples/sec (per-sample)"
- gen~ object containing: accum operator (or counter 0 100) -> out 1
  - The gen~ patcher uses classnamespace "dsp.gen"
  - Operators inside gen~ do NOT use tildes: use `accum` or `counter`, not `counter~`
  - Use `out 1` (not `out~`) to send signal back to MSP
- gen~ output -> *~ 0.01 (scale 0-100 to 0-1 range for scope) -> number~ + live.scope~
- Comment: "gen~ sees every single sample -- the most granular level"

**gen~ patcher JSON structure (from RESEARCH.md):**
- The gen~ object is a `newobj` with `text: "gen~"`
- It contains a nested `patcher` with `classnamespace: "dsp.gen"`
- Inside: use `accum` operator (simpler than counter for this demo) -- accumulates a value per sample
  - `accum 1 0 100` -- increment by 1 each sample, wrapping 0-100
  - Or use `counter 0 100` if accum doesn't work cleanly
- Connect accum/counter -> `out 1`
- The gen~ patcher needs `appversion` matching Max 9 (major: 9, minor: 1, revision: 1)

**Shared elements:**
- Title comment at top: "Three Levels of Processing in Max"
- ezdac~ at bottom center (shared DSP toggle for signal and sample columns)
- Annotation comments explaining the comparison:
  - "LEFT: Max scheduler sends messages at low rate (~once per millisecond)"
  - "CENTER: MSP processes audio in vectors of 64 samples"
  - "RIGHT: gen~ processes one sample at a time (compiled to native code)"
  - "Today we're learning MSP (center column). gen~ is a preview of what's deeper."

**Patch layout:**
- Three columns with clear vertical separation (~200px wide each, ~50px gaps)
- Left column x ~30-220, Center x ~270-460, Right x ~510-700
- Total patch rect approximately 750x500
- No Presentation Mode needed (per RESEARCH.md -- this is a comparison tool, not a performance patch)

**Output safety:**
- The phasor~ and gen~ columns produce signals but this patch is for visual comparison, not audio output
- No audio reaches dac~ -- the signals go to scopes and number~ only
- ezdac~ is needed only to activate DSP processing for the scopes to display

**JSON format:** Follow the same .maxpat JSON structure as existing patches (fileversion 1, appversion Max 9). Reference patches/01-hello-signal.maxpat for box/line structure conventions. Use unique IDs for all objects. Include `patcher.classnamespace: "box"` for the main patcher (default) and `"dsp.gen"` for the gen~ sub-patcher.
